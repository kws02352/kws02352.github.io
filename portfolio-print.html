금융권 OCR 서비스의 첫 단계로, 촬영 이미지에서 카드·신분증 영역과 꼭지점을 찾는 모델입니다. ONNX로 변환해 엔진에 전달하는 방식으로 배포되며, 다수 금융권 고객사 서비스에 탑재돼 약 3년간 운영됐습니다.

ROI Score 0.9410 → 0.9666 이전 CNN 대비 추론 속도 20% 향상 저가형 안드로이드 100ms 이하 · 1.1MB 특허 등록

OpenCV 방식의 구조적 한계

가이드 박스 안에서만 동작했고, 카드의 회전 방향을 몰라 0/90/180/270도를 모두 추론해야 했습니다. 위아래 판별에도 타이틀 영역을 따로 분석하는 처리가 필요했습니다.

  • 단일 추론으로 3채널 마스크를 출력하는 1-Stage 구조 설계: 카드 영역(ch0), 방향 판별용 타이틀 영역(ch1), 꼭지점(ch2)
  • ch0 마스크에서 꼭지점 후보를 뽑고 ch2의 코너 포인트와 매칭해 정밀한 4점 추출

4방향 반복 추론을 단일 추론으로 통합, 자유 위치·크기 입력 대응 → 특허 등록(제10-2837662호)

모바일 배포 제약

  • 파라미터 수와 추론 속도를 계속 측정하면서 구조를 실험하고, 속도 기준 안에서 성능을 최대로 확보

클래스 확장 후 성능 하락

지원 카드가 8종에서 11종으로 늘면서 ROI Score가 0.9633에서 0.9410으로 떨어졌습니다. 구조·데이터·Loss 세 방향에서 대응했습니다.

  • 구조 로컬 특성에 의존하는 CNN 백본을 TinyViT로 교체. 인코더에 행/열을 번갈아 쌓은 Area Attention, 디코더에 Linear Attention을 적용해 100ms 제약 유지
  • 데이터 백본 교체만으로는 성능이 오르지 않았음. 적용돼 있던 Augmentation 설정이 실제 촬영 환경과 어긋난 것을 확인하고 재설계
  • Loss MSE+CE의 단순 구조를 OHEM+Focal(클래스 불균형), Dice(영역 겹침), IoU, Distance-Transform Boundary Loss(경계 정밀도)로 재설계, LossWeightScheduler와 ModelEMA 도입

ROI Score 0.9666으로 확장 전 최고치(0.9633) 초과, 이전 CNN 모델 대비 추론 속도 20% 향상

ROI 탐지와 카드 분류의 중복 연산

영역 탐지와 카드 종류 분류를 별도 모델로 처리하면서 같은 이미지를 두 번 연산했습니다.

  • 두 과업을 하나의 모델에서 동시에 학습·예측하는 Multi-task 구조로 통합
  • 카드 마스크 채널을 분류 헤드의 공간 가중치로 쓰는 Seg-Guided Pool 설계로 두 태스크가 서로 보완
라이브 모델 운영

상용화 이후에도 신규 카드 추가와 고객사 실패 케이스 대응이 계속 필요했습니다.

  • 데이터 수집 → 원인 분석 → 재학습 → ONNX 재변환 사이클을 직접 담당
